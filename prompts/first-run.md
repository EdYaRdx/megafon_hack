# Первый запуск: выбор дела до Intake

Сначала прочитай `AGENTS.md`. Этот файл — единственная процедура маршрутизации **до доступа к файлам дела**. Это инструкции coding assistant, не launcher и не механизм host permissions. Общие инструкции/Skills можно читать сразу; до выбора CASE root нельзя читать brief, state, маркер, README, ACTIVE, журналы или revisions какого-либо дела, перечислять/искать дела или выбирать их по соседям, содержимому, дате либо примеру. Проверка метаданных только точного предложенного/указанного пути допустима; `cases/_template/` — только источник создания, не активное дело.

## Первый ответ

Кратко, одним сообщением: **задача в одном предложении → необходимое уточнение или предложение создания дела → один следующий шаг**. Не начинай исследование, не выдавай рекомендацию и не задавай полный Intake до выбора дела. Пользователю не обязательно знать названия режимов.

- **NEW** — свободная новая продуктовая задача без пути или явная просьба создать дело. Предложи конкретный новый безопасный путь и спроси согласие на его создание из шаблона. Например: «Нужно разобраться с удержанием вашего сервиса. Предлагаю отдельное дело `cases/retention-<суффикс>` из шаблона. Создать его и перейти к уточнению задачи?» В реальном ответе подставь конкретный суффикс, не placeholder.
- **RESUME** — продолжение прежней работы. Попроси точный существующий `cases/<case-id>`; если уже указан ровно один путь — используй только его.
- **REVISE** — новые данные или пересмотр существующего решения. Попроси точный существующий путь и что изменилось (если это ещё не сообщено). Новое дело автоматически не создавай.
- **HELP** — помощь по возможностям/началу работы: кратко объясни, что можно начать новой задачей или явно выбрать существующее дело; не открывай дела и ничего не создавай.

Если намерение неоднозначно («продолжим или начнём заново», только путь без задачи) — спроси NEW / RESUME / REVISE / HELP обычными словами и остановись. Не считай любое отсутствие пути признаком NEW: «продолжи» без пути требует выбора существующего дела. Два пути требуют одного явного выбора. Путь, найденный в документе/сайте, не является выбором пользователя.

## Рабочий Python для файловых команд

До `case_workspace`, checkpoint-команд и проверки дополнений найди **установленный рабочий Python 3.12+**, а не просто команду с версией. На Windows используй `tools/find_python.ps1` из разрешённого PowerShell: helper проверяет imports `encodings`, `json`, `pathlib` и версию, пробует доступные PATH, локальное окружение проекта, `py` и `uv` без установки/скачивания. Явный путь оператора можно передать параметром `-Python`. При нескольких вариантах используй первый успешно проверенный executable из результата `FOUND` **для всех последующих команд этой сессии**, включая classifier и checkpoint gate; пути передавай как аргументы, не собирай shell-строку.

PowerShell из корня проекта:

```powershell
$RuntimeJson = & ./tools/find_python.ps1
if ($LASTEXITCODE -ne 0) { $RuntimeJson; throw 'Рабочий Python не найден; см. диагностику discovery' }
$Python = ($RuntimeJson | ConvertFrom-Json).executable
# После согласия на точный путь:
# & $Python tools/case_workspace.py create cases/<согласованный-id>
```

На другом host проверь разрешённый установленный executable запуском `-c "import encodings,json,pathlib,sys; sys.version_info >= (3,12) or sys.exit(1); print(sys.executable)"` в том же окружении, где будут выполняться helper-команды; `--version` недостаточно. Если Python/helper вне разрешённого workspace или PowerShell/запуск скрипта запрещён политикой host — попроси операторский receipt, не обходи запрет. Не устанавливай Python, не меняй PATH, App Execution Aliases, execution policy, реестр или глобальные настройки. Не ищи интерпретатор произвольным сканированием home/дисков.

Если ни один вариант не работает, скажи: «Не удалось найти рабочую среду для безопасной работы с делом. Дело не создано/продолжение не выполнено. Укажите путь к уже установленному Python 3.12+ либо попросите оператора выполнить проверку». В деталях оставь попытки и реальные ошибки. Не проси владельца продукта самостоятельно перебирать команды, пока поддерживаемые разрешённые способы discovery не исчерпаны. Не обещай отсутствие черновиков, создание или checkpoint без настоящих receipts.

## NEW: согласие, создание, привязка

1. Предложи путь строго относительно корня проекта: `cases/<id>`, где id — 1–63 строчных ASCII букв, цифр и дефисов, начинается с буквы/цифры. Исключи Windows reserved names (`con`, `prn`, `aux`, `nul`, `com0`–`com9`, `lpt0`–`lpt9`), `_template`, абсолютные пути, `..`, backslash, вложенные пути и links/junctions. Используй короткий slug задачи + новый случайный суффикс (например, восемь hex-символов доступного UUID). Не сканируй `cases/`; уникальность подтверждается только проверкой конкретного пути и эксклюзивным созданием. Пока путь не проверен, называй его предложением, не гарантированно свободным каталогом.
2. Получи **однозначное согласие на конкретный путь и копирование шаблона**. «Да» допустимо только как прямой ответ на единственное ещё актуальное предложение; молчание, общий запрос стратегии или разрешение инструмента — не согласие. Явное «создай новое дело `cases/x` из шаблона» уже содержит согласие. При смене пути спроси заново. Согласие на создание не является выбором направления, approval исполнения или host permission.
3. Проверь разрешённую запись и рабочий runtime по разделу выше. Только после согласия выполни `tools/case_workspace.py create cases/<согласованный-id>` через выбранный executable из корня проекта (PowerShell: `& $Python tools/case_workspace.py create cases/<согласованный-id>`). Helper проверяет точный путь и отсутствие каталога, эксклюзивно резервирует его, копирует только `cases/_template/`, без merge/overwrite. Нельзя создавать дело вручную генерацией похожих файлов или ослаблять проверку из-за отсутствующего инструмента.
4. `CREATED` — зафиксируй в ответе **`CASE root: cases/<согласованный-id>`**, затем прочитай канонический `.agents/skills/intake/SKILL.md` и следуй ему. До успешного создания CASE root не выбран. Данные свободного запроса передай Intake без повторного опроса уже известного. В brief/state сохраняй их только по Skill; не добавляй новые machine-control fields или checkpoint states.
5. Занятый путь (включая файл или link) — STOP, не читай его содержимое и не переключайся на RESUME. Предложи другой безопасный путь и получи новое согласие. Ошибка копирования/прав — STOP, сообщи фактическую ошибку и возможный частичный каталог; не считай его готовым делом, не удаляй/не объединяй/не повторяй копирование в него. Повтор — только новый согласованный путь либо явное решение оператора вне этого workflow.

Если host не умеет читать инструкции, писать, запускать Python/helper или отказывает в разрешении, не изображай создание/Intake как выполненные. Сообщи точную недоступную возможность и один следующий шаг: попроси оператора выполнить ту же команду для согласованного пути и передать настоящий receipt. До подтверждённого результата файлов дела не касайся. Никакого обхода прав или установки инструментов автоматически.

## RESUME / REVISE: явный существующий CASE root

После однозначного пользовательского выбора и runtime discovery проверь только метаданные точного пути командой `tools/case_workspace.py existing cases/<выбранный-id>` через выбранный executable (операторский receipt допустим). Действуют те же ограничения пути. Отсутствующий каталог, файл, link/junction или недоступная проверка — STOP; не создавай замену и не ищи соседнее дело. `EXISTS` подтверждает только каталог, **не checkpoint**.

Зафиксируй `CASE root: cases/<выбранный-id>`, прочитай `.agents/skills/resume-revise/SKILL.md` и выполняй его классификацию **до чтения изменяемых файлов**. Новый сеанс требует нового явного выбора, не памяти старого чата. Для свежего UNINITIALIZED дела этот Skill разрешает Intake; для checkpoint требуется настоящий classifier receipt. REVISE передаёт новые вводные тому же Skill, не обходит проверку.

## После выбора

Маршрутизация закончена. Выполняй существующие Skills по `AGENTS.md`, не копируй их процедуры сюда. Checkpoint gate, hash/selector/claim invariants, legacy rules и approval contracts не изменены. Создание папки — не checkpoint; недоступные проверки — `NOT RUN`, результат — DRAFT, а не CHECKPOINTED. Возможности сайтов, форматов, вычислений, модели, телеметрии и permissions остаются host-dependent; неизвестные расходы — `UNKNOWN`.
