# Независимый аудит Codex E2E — R1/R2

**Объект:** сохранённый кейс `case/` и пользовательская диагностическая сводка `host-provenance.md`. Она записывает R1: Codex CLI 0.166.0, R2: Codex CLI 0.169.0; проверяемая версия агента указана как `a7701a5e4352710df7dc86a54abb3aca22a783f3` (Git в этом аудите не проверялся).

**Метаданные host:** `host-provenance.md` сообщает два разных Session ID, R1 22 exec calls/22 output records, R2 7/7, число записей JSONL 220/77 и 0 parse errors в обоих случаях; для каждого лога приведён SHA256. GPT-6 Luna High и времена R1 7m37s/R2 2m50s сообщались пользователем ранее, но не записаны в этой сводке/состоянии кейса. Сырые JSONL не включены и OMP напрямую не проверял.

**Итог:** **PARTIAL PASS.** Содержимое синтетического кейса проходит аудит; доступная summary содержит метаданные двух сессий и структурные результаты парсинга, поддерживающие раздельность R1/R2 на уровне этой сводки. Это не независимая проверка исходных JSONL и не доказывает успешность каждого вызова либо активацию Skills. REVISION-EVIDENCE-02 остаётся P2 из-за отсутствия полных исторических R1-копий изменённых документов.

## Метод и границы

Проверены все файлы `case/`: synthetic inputs, README, ledgers, options, decision, две стратегии, test plan, state/activity и четыре version snapshots. Входы `brief.md`, `concept-note.md`, `beta-survey.csv` сверены с указанными исходниками `cases/meal-planner-demo/`. Публичная страница AAPOR открыта напрямую по URL из S4; проверена Section III и её подразделы о questionnaire/instrument, population, sample/recruitment, precision, processing и limitations. Материалы не менялись; исходный E2E не повторялся.

Получены три независимых OMP read-only review исходного аудита; после provenance-обновления назначен один узкий consistency review. Независимость разных модельных семейств не установлена. В этой среде shell/PowerShell не запускались, поэтому хеши сырых логов не пересчитывались; указанные в `host-provenance.md` значения SHA256 и parser outcomes рассматриваются как результаты пользовательской диагностики, не как повторно проверенные сырые данные.

## Сопоставление host provenance

- **Наблюдаемо в репозитории:** `host-provenance.md` доступен и содержит отдельные разделы R1/R2, различные Session ID, CLI metadata, per-log SHA256, JSONL record/parse-error counts, `exec` call/output counts и списки путей skills. Сводка сама указывает, что значения получены пользователем из локальных Codex logs; raw JSONL не включены. `case/state.md:15-17` по-прежнему не фиксирует модель и точное runtime; `case/activity.jsonl` — журнал повествовательных записей.
- **Поддержано диагностической сводкой (не прямой проверкой JSONL):** R1 CLI 0.166.0, 220 records/0 parse errors, 22 `exec` calls/22 output records; R2 CLI 0.169.0, 77 records/0 parse errors, 7 calls/7 output records. В сводке записаны два разных Session ID и ссылки в R1 tool arguments на все шесть навыков (`host-provenance.md:6-21`). Это метаданные/структурные результаты, сообщённые пользователем; сырые логи не представлены.
- **Ограничение интерпретации:** parser success и наличие output records не подтверждают, что команды завершились успешно или дали ожидаемый результат. Пути `SKILL.md` в аргументах подтверждают только наличие ссылок/путей в записанных аргументах; они не доказывают фактическое чтение содержимого, автоматическую активацию или применение навыка. Я не проверял исходные JSONL и не утверждаю обратного.

Ни первый reviewer, ни этот аудит не проверяли сырые JSONL; skill activation и семантический успех tool calls не подтверждены.

## Findings

### P0 — нет

Не найдено содержимого, делающего решение небезопасным или явно недостоверным.

### P1 — нет

В проверенных артефактах не выявлен дефект обязательной продуктовой логики или доказательной цепочки.

### P2 — доказательная упаковка E2E, не дефект продуктового решения

1. **HOST-EVIDENCE-01 — структурная provenance описана, raw evidence и skill activation не подтверждены.** `host-provenance.md:6-21` сообщает R1 Codex 0.166.0 (220 JSONL records, 0 parse errors, 22 exec calls/22 outputs) и R2 0.169.0 (77 records, 0 errors, 7/7), разные Session ID, per-log SHA256 и skill-path references. Эти данные поддерживают наличие двух сессий и структурную parseability в пользовательской диагностической сводке. Сама сводка указывает, что raw JSONL не включены и не проверялись OMP (`:25-35`). Tool outputs не гарантируют успешность; пути skills не доказывают активацию. **Действие:** сохранить сводку отдельно от сырых журналов; не заявлять автоматическую активацию/успешность всех calls без более сильных проверок. Повтор E2E не требуется.
2. **REVISION-EVIDENCE-02 — неполный исторический diff R1→R2.** Сохранены R1 snapshots состояния и решения, но не R1 варианты, стратегии и test plan; `activity.jsonl:10` сообщает об изменениях без полных before/after копий. Поэтому смысл R2 подтверждается по текущим файлам и журналу, но exact diff этих материалов не восстанавливается. **Минимум:** не переписывать тестовые артефакты; для следующих revision-тестов сохранять snapshots изменяемых outputs или машинно-читаемый diff вместе с hashes.

Это P2 ограничения проверяемости пакета, не основания переписывать уже полученный case. Других P0/P1/P2 дефектов в проверенных product outputs не найдено.

## Итог Codex E2E и решение о демонстрации

- **Codex E2E:** **PARTIAL PASS, с усиленной структурной provenance.** Сохранённые выходы внутренне связны; `host-provenance.md` документирует для двух различных Session ID версии R1/R2 и результаты структурного разбора логов. Эти сведения получены пользовательской локальной диагностикой; исходные JSONL не проверялись. Подтверждены summary-level metadata, но не семантический успех каждого tool call, skill activation или гарантированная эквивалентность повторного прогона.
- **Готовность к synthetic demo:** **ДА, для guided walkthrough файлового decision workflow**. Показывать 20% / 62.5% / 12.5% с точными знаменателями; четыре варианта; условную рекомендацию; C6 как fictional-only; R2 refinement counterexample protocol; human gates. Не утверждать реальный спрос, launch readiness, автоматическую активацию skills или независимую верификацию new-chat execution.
- **Достаточность для Codex-демо:** **ДА для guided synthetic demo по сохранённым артефактам.** Они достаточны для демонстрационного walkthrough; воспроизводимость идентичного нового прогона не установлена. Сводка документирует две версии/сессии, counts и hash fingerprints, но не заменяет raw logs и не доказывает semantic success/skill activation. Демонстрировать в Codex четыре варианта, условную рекомендацию, точные знаменатели, согласованные стратегии, human gates и R2 handling. Cursor — дополнительная portability-проверка, не обязательный gate Codex-демо; остаётся полезной для общего портируемого продукта.
- **Полный конкурсный acceptance:** не пройден. Codex-сценарий пригоден для заявленного synthetic demo с указанными ограничениями. Остаются общие gates исходной Goal: официальный демо-бриф, retention-метрик contract, видео и подача; Cursor проверяется дополнительно на переносимость. Этот отчёт не утверждает полную готовность продукта.
