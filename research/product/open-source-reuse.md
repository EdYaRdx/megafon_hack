# Open-source reuse review

**Method.** Inspected actual public code/examples/docs and license files/metadata, not README marketing alone, for the priority projects in the active brief. Sources are the live `main`/`master` branches read 2026-11-11 unless otherwise stated; mutable branch observations are not pinned release guarantees. No package was installed or executed. Verdicts: **USE DIRECTLY** = adopt a specification/convention rather than copy implementation; **ADAPT METHOD** = independently write a small procedure inspired by the inspected behavior; **REFERENCE** = retain as future option/source; **REJECT** = don't include in initial folder-based product. “License observed” refers to repository top-level declaration, not every dependency, bundled model, dataset, or individual skill. No source files are copied in this research.

## Synthesis by need

- **Use directly:** Agent Skills' folder/spec convention only; no executable implementation adopted.
- **Adapt method:** stateful step/deliverable sequencing (two PM skill examples, independently redesigned), explicit weak-claim taxonomy (multi-agent research reviewer, strengthened beyond citation presence), bounded perspective-guided question generation (STORM), and structured review rubric (Docling PR review skill).
- **Reference, not dependency:** MarkItDown and Docling for parser candidates; Promptfoo for later red-team cases; DeepEval for optional evaluation metric categories; GPT Researcher for research decomposition.
- **Reject for initial product:** full multi-agent/service stacks and installation of any parser/evaluation package without a fixture demonstrating necessity. **Product-Manager-Skills content is also rejected for copying** due CC BY-NC-SA 4.0/non-commercial ShareAlike constraints; only high-level non-protectable methodology is independently re-expressed, with legal uncertainty not adjudicated.

## Review limits / follow-up

- Moving branches were not commit-pinned. Pin commit/release and re-check package, model, script, prompt and transitive dependency licenses before any implementation reuse.
- A repository's top-level license does not necessarily cover every model, dataset, embedded external asset, prompt, skill, or dependency.
- Only public source was inspected; no setup script/package install/test execution occurred.
- These are actionable design judgments, not independent runtime benchmarks or legal advice.
