## Keep / present / archive / do not ship

Категории описывают **разные решения**: KEEP — хранить в Git; PRESENT — показывать первым; ARCHIVE — сохранять историю на прежнем пути; EXCLUDE FROM JURY PACK — не включать операционное/приватное в передачу. Архив не означает удаление.

| Группа | Решение для Git / навигации | Решение для конкурсной копии |
|---|---|---|
| `README.md`, `docs/README.md`, Quick Start, architecture, contest-demo, submission-description | **KEEP / PRESENT** | Основной путь чтения, не новая инструкция агенту |
| `AGENTS.md`, `.agents/skills/`, `references/`, `prompts/first-run.md` | **KEEP** | Ядро продукта; first-run — канонический маршрут, не только fallback |
| `cases/_template/`, `tools/`, `tests/`, `.github/workflows/`, `.gitattributes`, `.gitignore` | **KEEP** | Воспроизводимость; tools — Python stdlib, не сервер. `cases/** -text` защищает точные байты; CI/check_repository требуют Git checkout |
| `cases/mobile-product-strategy-demo/` **целиком** | **KEEP / PRESENT**, только с предупреждением о происхождении | Включать **только после разрешения прав/доступа**. D0001–D0003, PDF/PNG/TXT, inputs, ledgers, manifests, receipts, расчёты и drafts не вырезать. Исторические mutation scripts не запускать |
| `cases/pantrypath-week4-20261115/` | **KEEP**, дополнительный синтетический пример | Полезный запасной пример; не замена конкурсному PDF и не новый E2E |
| Остальные кейсы из [каталога](../cases/README.md) | **KEEP / ARCHIVE**, не первый экран | Не нужны в начальном маршруте жюри. Физически исключать лишь после проверки входящих ссылок и тестов, не объявлять возраст доказательством ненужности |
| `docs/evaluation.md`, release verification/demo-evidence, submission-checklist | **KEEP**, доказательства по ссылке | Нужны вместе с указанными ими evidence-файлами; старые FAIL и UNKNOWN не скрывать |
| `docs/repository-inventory.md`, `implementation-status.md`, `*handoff*`, `research-plan.md`, старые release reports | **ARCHIVE на месте** | Не начальное чтение; ссылки/датированные доказательства сохранять, не выдавать старые инструкции за актуальные |
| `research/`, `MGIMO_RESEARCH_TO_IMPLEMENTATION.md` | **ARCHIVE на месте** | Только справочная история; не обязательный runtime. Не исключать файлы, на которые ссылается оставленная evaluation/документация |
| `.omp/`, overnight launchers/prompts, `prompts/research-smoke.md` | **ARCHIVE на месте** | **EXCLUDE FROM JURY PACK** как development-инфраструктуру; без них продукт запускается. Ссылки на исключённое тоже проверить |
| `START-HERE.txt`, `docs/submission-architecture.md` | **KEEP**, короткие указатели | Не создавать вторые канонические Quick Start/architecture |
| `.git/`, `.local/`, credentials, `.env`, raw host sessions, приватный оригинал R0001–R0003, локальные тестовые каталоги/профили | Не добавлять новое приватное; существующую историю не переписывать | **EXCLUDE FROM JURY PACK** безусловно |
| Кандидаты на **REMOVE** | **Нет**: отсутствие зависимостей не доказано ни для одного исторического файла | Не удалять ради красивого дерева |

**Почему пока не переносим целые каталоги:** в файлах существующих дел есть абсолютные и относительные ссылки, SHA-256 зависимости, исторические locators и проверки. Перемещение ради косметики повышает риск регрессии и не облегчает основной путь, если README и навигация уже ведут к продукту. Физическое выделение архива — отдельное изменение после карты зависимостей и тестов.

## Связанные, но отдельные проекты

| Проект или направление | Что можно использовать | Почему не переносим его код |
|---|---|---|
| **Deep_research_CLI / OptiLLM / Polza** | Методологию provenance, бюджетных оговорок и review; только подтверждённые выводы через ссылки в reports | Платная исследовательская обвязка, токены и proxy **не являются runtime-зависимостью** этого агента; учёт стоимости внутренних вызовов может быть `UNKNOWN` |
| **OMP** | Датированные отчёты разработки, independent review и результаты release-checks | OMP создавал и проверял репозиторий; пользовательскому агенту он не нужен |
| **Agent Platform / DSH** | Идеи строгого разделения роли автора, проверки и разрешений | Полноценный control-plane и SQLite runtime решают другую задачу; ТЗ просит папку агента, не автономную платформу |
| **mgimo-omp-docker / локальные worktrees** | Инструкции проверки из clean host после независимого подтверждения | Содержат локальные окружения, историю испытаний и потенциально машинные пути |
| **Council / OpenClaw / OpenHands / внешние MCP** | Точечные идеи independent review и инструментальной интеграции | Не проверены как необходимые дополнительные runtime-компоненты; новые зависимости не окупаются без измеренной пользы |

Это **границы интеграции**, не заявление, что все перечисленные системы успешно работали в конкурсном E2E. Сопутствующие репозитории имеют собственные лицензии, настройки, расходы и безопасность. Не копируйте их API-ключи, configs, результаты запуска или README целиком.

## Рекомендуемый состав передачи жюри

**Безопасная основа после разрешения прав:** проверенный tracked snapshot выбранного commit **без `.git`**, не ZIP всего локального рабочего каталога. Не брать `.local/`, untracked-файлы, caches, пользовательские настройки и соседние worktrees. Это рекомендация состава, **не уже собранный или одобренный пакет**.

Для компактной копии исключать development-группы по таблице, затем проверять **замыкание ссылок**: каждый оставленный относительный Markdown target и каждая manifest dependency должны присутствовать. Нельзя просто убрать весь `research/`: evaluation ссылается на его негативные результаты. Если замыкание не проверено, оставить tracked исторические evidence, а не рассылать копию с битыми ссылками.

**После сборки:** реальные gate/classify/inventory над D0003, сравнение всех case bytes с выбранным snapshot, проверка Markdown targets/fragments и приватности. Штатный repository checker использует Git index и не является проверкой ZIP; CLI Resume работает без `.git`. Unit suite/CI воспроизводить в полном developer checkout, а не обещать их работу на урезанной копии. PDF, реальные кадры, видео и фактические расходы передаются только по отдельным закрытым gates.

**Не передавать:** Git history с личными путями, исходное приватное дело R0001–R0003, raw sessions, локальные конфигурации моделей, секреты и внутренние неразрешённые материалы. Исходные R-ревизии нельзя просто объявить эквивалентом D-копии; историю преобразования объясняет [EXPORT.md](../cases/mobile-product-strategy-demo/EXPORT.md).

Текущий репозиторий оставлять **PRIVATE**. После решения о правах на `Пример брифа.pdf` допустимая передача — ZIP текущего согласованного дерева **без `.git`** или новый проверенный history-free репозиторий. Не делать существующую историю PUBLIC. Лицензию и доступ жюри определить отдельно; пустое поле лицензии не означает permission to redistribute.

## Контроль перед финальной публикацией

1. Сверить PDF-образец с актуальным файлом и требованиями в личном кабинете MGIMO, подтвердить право передачи документа и производных материалов.
2. Пройти [checklist подачи](submission-checklist.md) и [release verification](release/contest-rc-verification.md).
3. Проверить пути/ссылки и tests на финальной копии; отдельно проверить реальное открытие в выбранном host и `RESUME CASE`.
4. Добавить **настоящие** скриншоты и видео только после приватной проверки (см. [media guide](demo-media-guide.md)).
5. Для GitHub вручную задать краткое описание, аккуратные topics и лицензирование **только после решения владельца прав**.

Любые изменения опубликованных `D0001–D0003` должны проходить существующий протокол; документационный PR не меняет их байты.
