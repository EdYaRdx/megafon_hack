# Карта репозитория

Репозиторий содержит файлового продуктового агента, основной видеокейс и техническую историю разработки. Для использования достаточно [быстрого запуска](quickstart.md); читать архивы и устанавливать OMP не требуется.

## Основной маршрут

[README](../README.md) → [реальный видеокейс](video-e2e.md) → [продуктовая](../cases/family-multinumber-video/strategy-product.md) и [коммуникационная](../cases/family-multinumber-video/strategy-communication.md) стратегии.

Для собственной задачи: [Quick Start](quickstart.md). Для жюри: [описание решения](submission-description.md) и [результаты проверок](evaluation.md). Для устройства продукта: [архитектура](architecture.md).

## Где что находится

| Путь | Назначение |
|---|---|
| `AGENTS.md` | Контракт работы агента, правила доказательств и полномочий |
| `.agents/skills/` | Шесть канонических Skills |
| `references/` | Методика источников, claims, метрик и безопасности |
| `prompts/first-run.md` | NEW / RESUME / REVISE / HELP и выбор точного дела |
| `cases/_template/` | Шаблон нового дела и checkpoint-протокол |
| `cases/family-multinumber-video/` | Основной опубликованный видеокейс D0001–D0003 |
| `cases/README.md` | Каталог примеров и QA-фикстур |
| `tools/`, `tests/`, `.github/workflows/` | Python helpers, автоматические проверки и CI |
| `docs/` | Запуск, кейс, архитектура, описание для жюри и оценка |
| `docs/assets/` | Подлинный кадр видео и описание его происхождения |
| `docs/archive/README.md` | Отдельный индекс технической истории и inventory A/B/C |

Модель, IDE, сетевые инструменты и разрешения предоставляет coding assistant. В репозитории нет отдельного сервера или скрытого платного исследовательского runtime.

## Дело — единица результата

В новом деле сохраняются входные материалы, источники, evidence, claims, альтернативы, решение, обе стратегии, план проверки и state. Checkpoint хранит snapshots и их зависимости; `ACTIVE.json` выбирает сохранённую версию. Прежние ревизии доступны после пересмотра. [Подробный формат](architecture.md#компоненты-и-хранение-данных).

Не редактируйте демонстрационные дела ради своего запуска. У основного примера даже README включён в export-map: обновления внешней навигации находятся в [walkthrough](video-e2e.md), а не в пересчитанной задним числом карте. Исторические case helpers не являются запускателями продукта.

## Текущий продукт и архив

| Категория | Решение |
|---|---|
| **A — текущий продукт** | Runtime-инструкции, Skills, helpers, шаблон, основной кейс и пользовательские документы остаются в основном маршруте |
| **B — технический архив** | Старые release/integration/qualification отчёты, handoff, исследования и прежние демо сохраняются через отдельный архивный индекс |
| **C — устаревшая подготовка** | Overnight launcher и прежние video/media-планы подготовки исключены из основного маршрута; удаление не выполняется, пока существуют входящие ссылки |

Полный поимённый [inventory и безопасные решения A/B/C](archive/README.md) содержит проверенные зависимости. Архив выделен навигацией, без перемещения файлов, на которые могут ссылаться сохранённые материалы. Предыдущие отрицательные испытания не исчезают и не становятся текущими PASS.

## Передача материалов

Передавайте tracked-репозиторий или согласованную копию с полным делом и его зависимостями, а не весь локальный рабочий каталог. Не включайте `.local/`, исходный персональный R-кейс, raw sessions, credentials, `.env`, caches или пользовательские профили.

Основной D-кейс — самостоятельный обезличенный derivative, не исходная R-история. PDF и кадры распространяются с учётом прав и условий конкурса, без автоматически назначенной лицензии. Доступ жюри к GitHub и видео проверяет владелец; этот документационный release не меняет visibility и не выполняет подачу. [Ручной checklist](submission-checklist.md).
