# Публичная видимость: что раскроется и что проверено

Репозиторий остаётся PRIVATE. Merge PR32 и документационная подготовка не являются разрешением изменить visibility, выдать доступ третьим лицам или отправить заявку.

## Категории сведений при PRIVATE → PUBLIC

| Категория | Что может увидеть внешний читатель | Что это означает для проекта |
|---|---|---|
| Текущее содержимое репозитория | README, docs, исходники/Skills/tools/tests, все tracked кейсы, учебные PDF/PNG/OCR, результаты/журналы | В main включён только privacy-safe новый кейс, исходный host-лог/account snapshot не скопирован |
| История и remote refs | Старые версии файлов и удалённый из текущего дерева текст, ветки/теги, commits/messages, имена/email/время авторов | Исторические локальные пути профиля сохраняются; исправление README не удаляет старые blobs |
| Обсуждение разработки | Доступные вместе с репозиторием PR/issues/comments/reviews и release-материалы | Текст инженерных решений и прежние FAIL/ограничения тоже могут стать публичными; это не новые коммерческие доказательства |
| Actions | История workflow и логи | Даже когда текущие файлы очищены, надо отдельно учитывать сохранённые CI logs; это прямо описано GitHub |
| Ссылки на внешние материалы | URL видео, методик и источников | Репозиторий не выдаёт автоматически права на Drive/видео/исходные материалы и не доказывает права распространения |
| Копирование | Публичный код можно просматривать и fork-нуть | Последующее изменение доступа не отзовёт уже сделанные копии |

[GitHub Docs: изменение visibility](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility) подтверждает публичность кода, fork-возможность, activity и Actions history/logs. Это описание последствий, а не выполнение изменения.

Паттерн-совпадений email/credential/private-key/current-account/home path в текущем дереве не найдено. PNG metadata проверены, pixels не проходили новый полный визуальный review. Значения профиля здесь намеренно не повторяются. Файлы: docs/demo-media-guide.md и .omp/profiles/qualification-supervised.yml. В текущем дереве user-home примеры являются placeholders. История не переписана.

Новая целевая проверка main и добавленных документов фиксируется в [main-submission-checks.json](main-submission-checks.json): scope, counts, hashes, реальные результаты и ограничения. Сканирование не выполняет найденные команды и не следует внешним путям.

## Что не включено в main

- Приватные qualification worktrees, их .git и полные raw host transcripts.
- Исходный LinguaStep R0001 с machine-specific paths и shared-account quota/credit snapshot.
- Два pre-existing untracked файла основной рабочей копии: они не staged и не публикуются этим изменением.
- API keys/cookies/приватные сессии как материалы продукта не допускаются.

Новый [LinguaStep D0001](../cases/linguastep-retention/EXPORT.md) — отдельная производная, с заново вычисленными hashes и собственной картой происхождения. Human approval источника не переносится на исполнение производной.

## Решение владельца

Владелец отдельно решает, предоставить ли жюри доступ при PRIVATE или подтвердить PUBLIC с пониманием исторических данных. Авторская metadata и обычные пути ранее обсуждались в [чек-листе](submission-checklist.md); это не разрешение на секреты или новую публикацию персональных сведений.

Перед PUBLIC нужно подтвердить приемлемость исторических путей/metadata, права на учебные материалы, внешние links и доступы. Ни visibility, ни history rewrite, ни выдача доступов, ни конкурсная отправка этой работой автоматически не выполняются.
