# Медиа-план: README, скриншоты и обязательное видео

**Статус:** план производства, не подтверждение записи или публикации. Пользовательский интерфейс конкурсного продукта — **реальный coding assistant (Codex/Cursor)** и файлы проекта. Не рисуйте фальшивый собственный веб-сервис.

Цель — чтобы зритель за **20–30 секунд** понял ценность, за **2 минуты** увидел настоящий вход/выход, а при желании смог пройти до источника, решения и проверяемого checkpoint.

**Доступные материалы:** в tracked-дереве есть PDF и 11 PNG его страниц, но это изображения документа, **не screenshots взаимодействия Codex/Cursor**. Страницы 1 и 3 просмотрены при аудите; на них прямо указаны вымышленный оператор и учебные числа. Разрешённых кадров ассистента, GIF или готового видео в дереве не найдено. Использовать страницы брифа можно только после решения о правах.

## Что действительно стоит показывать

| Материал | Что должно быть в кадре | Зачем | Где использовать |
|---|---|---|---|
| **01. Начало работы** | Codex/Cursor с естественным запросом, предложением CASE и явным подтверждением пути | Самостоятельное начало, а не заранее написанная стратегия | Видео и кадр для конкурсного документа; не отдельный README GIF |
| **02. Работа с брифом** | 1–2 страницы `Пример брифа.pdf` рядом с записью о происхождении, страница/источник → evidence → claim | Отделение исходных чисел от рассуждений | Видео; в README лучше ссылка на [кейс](contest-demo.md) |
| **03. Сравнение альтернатив** | Короткий фрагмент `options.md`: семейное предупреждение, кабинет, собственные номера, статус-кво и остановка | Обоснованный выбор вместо единственного ответа | README preview или 2-й скриншот |
| **04. Human gate** | Реальное сообщение PO и `decision.md`; видно, что приоритет ≠ разрешение пилота | Человек при существенном выборе | Видео |
| **05. Две стратегии** | Читаемые `strategy-product.md` и `strategy-communication.md`, выделены аудитория, барьер, сообщение, план проверки | Основной deliverable конкурса | README preview, видео |
| **06. Проверяемый расчёт** | `strategy.md`: 279 → 285 млн ₽, 500 ₽/месяц, условные 14 000 и явный `UNKNOWN` | Прозрачность и честность модели | Видео, необязательно в README |
| **07. Новый чат — Resume** | **Действительно новая сессия**, команда с точным CASE path, восстановление D0003 и проверка данных | Обязательное продолжение после перерыва | Ключевой фрагмент видео; единственный README GIF и кадр для конкурсного документа |
| **08. Ревизия после замечаний** | Сопоставление исходного R0002 и последующего R0003 (или производных D0002/D0003) с явным provenance | Дополнительная возможность пересмотра без потери истории | Видео, описание для жюри |

**Не добавлять:** фото МегаФона/офисов/людей из стоков, вымышленные mockups интерфейса, рекламные AI-арты, непроверенные графики роста, псевдо-видео, которые изображают несуществовавший real-time запуск. Для файла агента важнее **подлинный UX рабочего ассистента**, чем декор.

## Рекомендуемое оформление GitHub README

Пока нет очищенных кадров, оставляем на первом экране **Mermaid-схему**, рабочую команду и ссылки на настоящее дело. Это лучше пустого `assets/` и изображений с неподтверждённым статусом.

Когда подготовлены и проверены материалы:

- **Один главный скриншот** (горизонтальный, приблизительно 16:9): реальный ответ ассистента с сохранённым решением, одним основанием и следующим шагом; рядом видны файлы двух стратегий. Он должен показывать результат, а не только создание папки. Не вмещайте обе стратегии целиком и не показывайте личный desktop.
- **Один компактный GIF/WebP 6–12 секунд**: новый чат → точный Resume → восстановленное решение, только из **фактической записи**; ожидание можно вырезать с подписью «монтаж / ожидание сокращено». Не пытайтесь выдать многочасовое исследование за 6 секунд. GIF не заменяет обязательное видео.
- **Одна ссылка на полное видео** с реальным превью-кадром и короткой подписью. Не встраивать крупный MP4 в Git-историю, чтобы clone/ZIP оставались лёгкими.
- Подробные кадры из источников, стратегий и расчётов хранить в конкурсном документе или `docs/assets/demo/` **после** проверки приватности и разрешений, а не в виде десяти скриншотов на главной странице.

Все фактические изображения должны иметь содержательный alt-текст. Если скриншот трудночитаем при уменьшении до ширины мобильного экрана, разбейте его или дайте ссылку на исходный документ. Не добавляйте «Verified / Winner / Official Megafon» badges без оснований.

## Один сценарий, без дублирования

Точные таймкоды, длительности, названия кадров, цели и размещение — в единственном [storyboard на 9:30](demo-video-script.md). Он разделяет короткую реальную проверку нового дела, просмотр подготовленных D-артефактов и фактический Resume в новой сессии. Запись ещё не выполнена; нельзя выдавать эти три вида материала за один непрерывный live E2E.

Сокращайте ожидание только с подписью «ускорено»/«монтаж». Архивный выбор PO и сравнение D0002/D0003 подписывайте «сохранённые материалы». Новое согласие на создание тестового дела не является историческим выбором PO из R0002.

## Перед захватом экрана

1. Используйте **отдельную чистую копию** проекта/тестовое дело. Закройте посторонние терминалы, вкладки, уведомления, личные файлы и пользовательские журналы.
2. Сверьте допустимость распространения `Пример брифа.pdf`, его страниц и производных screenshots. Пока прав нет — **не публикуйте** эти кадры.
3. Уберите персональные имена, `C:/Users/...`, почту, токены, названия личных рабочих профилей, private repo URLs и сведения о платежах. Проверяйте не только картинку, но и аудиодорожку, metadata и превью.
4. Для видео используйте читабельный шрифт/масштаб 125–150% и выделение курсором; не рассчитывайте, что зритель прочтёт мелкий PowerShell лог. Для скриншота оптимальна короткая демонстрация одной мысли.
5. Проверьте переход от нового чата к `D0003` на **упакованном производном кейсе**. Если живой E2E не выполнен, скажите об этом вместо утверждения `PASS`.
6. Просмотрите экспорт перед загрузкой. Видео — на разрешённом сервисе по ссылке; жюри должно иметь доступ без запроса прав.
