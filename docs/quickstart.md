# Быстрый старт

Откройте проект в coding assistant и задайте продуктовый вопрос обычными словами. Агент предложит отдельное дело, запросит согласие на конкретный путь и после безопасного копирования шаблона перейдёт к Intake. Копирование создаёт начальные файлы, а не готовое решение.

[← Главная](../README.md) · [Готовый пример](pantrypath-demo.md) · [Архитектура](architecture.md)

## Требования

Нужны локальная копия репозитория, модель и coding assistant с чтением/записью файлов. Для создания/проверки пути штатным `tools/case_workspace.py` нужен **Python 3.12+ и разрешённый запуск команд** либо оператор, выполняющий те же команды с настоящим receipt. Backend, база данных, пакеты, launcher и новые MCP не нужны. Для checkpoint дополнительно обязательны существующие gates `tools/case_protocol.py`.

Доступ к сайтам и вычислениям зависит от выбранной среды. Используйте только разрешённые материалы; не помещайте в репозиторий пароли, персональные данные или конфиденциальные документы.

SHA-256 должны вычисляться реальным доступным инструментом по сохранённым байтам. Если среда не умеет считать hashes или запускать shared gate, заранее договоритесь об операторской помощи; она должна быть отмечена в receipts. Без этого результат остаётся DRAFT, а не проверенным checkpoint. Подписка/доступ к модели и файловым инструментам предоставляются выбранной средой, не этим репозиторием.

Модель, подписка/API и стоимость задаются вашей средой; ключи и аккаунты проект не поставляет. До первого вызова укажите allowance денег/времени и разрешённые инструменты. Оценочный monetary guard, останавливающий новые запросы, не гарантирует предел инвойса; недоступные расходы/телеметрию отмечайте UNKNOWN. Операторские ключи оценки, приватные traces и старые ответы не нужны для обычного ручного дела.

## 0. Получите и откройте проект

Если проекта ещё нет на компьютере, выберите один из способов. Для закрытого репозитория у вашей учётной записи должен быть доступ.

**Git clone** — выполните в терминале:

```bash
git clone https://github.com/EdYaRdx/megafon_hack.git
cd megafon_hack
```

**Download ZIP**

1. На [странице репозитория на GitHub](https://github.com/EdYaRdx/megafon_hack) выберите **Code → Download ZIP**.
2. Полностью распакуйте архив: Windows — **Извлечь всё / Extract All**; macOS / Linux — штатным архиватором.
3. Откройте извлечённую папку проекта, например `megafon_hack-main`. Имя зависит от выбранной ветки/тега; внешняя папка распаковки может содержать ещё один вложенный каталог.

В обоих случаях откройте в среде работы с ИИ **корень проекта**, где находятся `AGENTS.md`, `.agents/skills/`, `cases/`, `tools/` и `prompts/`. Операторские команды ниже выполняются из этой же папки. Не работайте внутри нераспакованного ZIP. Конкретные редакторы и настройки автопоиска инструкций здесь не сертифицированы.

### Cursor и другие coding assistants

В Cursor используйте **Open Folder** для корня репозитория и новый Agent/chat. Попросите прочитать `AGENTS.md` и `prompts/first-run.md`, затем напишите задачу. В другой совместимой среде выполните тот же workflow. Если host не обнаружил Skills автоматически, попросите прочитать нужный `SKILL.md`. Это инструкция, не сертификат работы всех версий Cursor/других hosts.

Рабочий каталог сам по себе не ограничивает доступ процесса. Права на файлы/сеть задаются host; используйте только разрешённую область без секретов и чужих данных.

## 1. Задайте задачу и выберите дело

Первое сообщение, без заранее созданной папки:

> Прочитай AGENTS.md и prompts/first-run.md. Помоги понять, почему падает удержание нашего сервиса.

Первый ответ агента: **краткая задача → предложение создания/необходимое уточнение → один следующий шаг**. Для новой задачи агент предложит конкретный путь вроде `cases/retention-a83f09c2` (это пример, не путь для копирования) и попросит согласие на копирование шаблона. Ответьте «Да, создай предложенное дело из шаблона» либо укажите другой безопасный путь. Общая просьба о стратегии и разрешение инструмента не заменяют согласие на создание.

Только после согласия агент проверяет точный путь и выполняет эксклюзивное копирование. Успех подтверждается реальным `CREATED` и строкой `CASE root: cases/<ваш-id>`, после чего начинается существующий Intake. Если путь занят, агент не читает его содержимое, не объединяет папки и просит согласие на другой путь. Неудачная/частичная копия не считается делом для продолжения.

| Что хотите | Что написать |
|---|---|
| NEW | Новую продуктовую задачу обычными словами; путь агент предложит |
| RESUME | «Продолжи дело `cases/<мой-id>`» с фактическим существующим путём |
| REVISE | «Пересмотри дело `cases/<мой-id>`: изменилось …» |
| HELP | «Как начать работу и что ты умеешь?» |

Название режима писать необязательно. «Продолжи» без пути требует вашего явного выбора; два пути или «продолжим или начнём заново» — уточнения. Агент не сканирует дела и не угадывает по датам/содержимому. HELP не читает файлы дел и ничего не создаёт.

### Если команду выполняет оператор

Сначала согласуйте **точный новый путь**. `python` ниже — доступный Python 3.12+; проверьте его версию и используйте рабочий executable своей среды. Замените пример фактическим согласованным путём:

```sh
python --version
python tools/case_workspace.py create cases/my-new-case
```

Команда не запускает модель, не получает за вас согласие и не создаёт checkpoint. Она отказывается от merge/overwrite и возвращает `CREATED` только после копирования. Передайте агенту реальный stdout/stderr/exit code. Если helper/Python, запись или permission недоступны, агент должен остановиться; он не генерирует похожий шаблон вручную и не изображает успешный запуск.

Пути helper — строго `cases/<id>` относительно проекта: 1–63 строчных ASCII букв/цифр/дефисов, начало с буквы/цифры; без reserved Windows names, `_template`, `..`, backslash, вложенных и абсолютных путей, symlinks/junctions. Это узкая проверка файловой операции, не OS sandbox: не допускайте параллельного изменения структуры каталогов другими процессами.

Для выбранного существующего дела:

```sh
python tools/case_workspace.py existing cases/my-existing-case
```

`EXISTS` означает только наличие каталога. Далее агент обязан выполнить классификацию Skill `resume-revise`; это не доказательство checkpoint и не разрешение прочитать mutable roots до классификации. Не создавайте замену отсутствующему делу автоматически.

## 2. Пройдите Intake

Агент читает канонический Skill и маркер **созданного/выбранного** дела. Уже сообщённые данные переносит без повторного опроса. Уточняются решение и владелец, цель и аудитория, срок/ограничения, разрешённые материалы и существенные неизвестные; неизвестное остаётся `UNKNOWN`. Бриф можно дополнить вручную в выбранном CASE root.

Разрешённые документы/таблицы положите в `inputs/` внутри дела либо укажите ссылки в brief. Для CSV опишите колонки, единицы, eligible population и пропуски; для документа — версию и страницу/раздел; для сайта — точный URL и дату условий. Недоступный PDF/XLSX/сайт требует читаемого экспорта либо явного пробела, не выдуманного чтения.

## 3. Продолжайте существующий workflow

Отвечайте на существенные вопросы. После сравнения минимум трёх направлений, включая статус-кво, прочитайте возражения и **сами подтвердите выбранное направление** либо запросите доработку. Попросите сохранить обе стратегии, план проверки, основания и ограничения. Создание дела, выбор направления и approval внешнего исполнения — разные действия; прежние approval contracts не изменены. Без достаточных данных — конкретные пробелы и следующий способ проверки, не вымышленные выводы.

## 4. Откройте результат

Все имена файлов в таблице относятся к выбранному CASE root, не к корню проекта.

| Файл | Содержимое |
|---|---|
| `decision.md` | Рекомендация, её основания и ограничения |
| `options.md` | Разные направления, включая статус-кво и остановку |
| `strategy-product.md` | Аудитория, ценность, выбранный продуктовый путь |
| `strategy-communication.md` | Аудитория сообщения, обещание, подтверждение и каналы |
| `test-plan.md` | План проверки гипотезы |
| `sources.jsonl` → `evidence.jsonl` → `claims.jsonl` | Проверяемая связь решения с материалами |
| `state.md` и `revisions/` | Текущий этап и история сохранённых решений |

[Посмотреть заполненный пример PantryPath](pantrypath-demo.md). Пример полностью синтетический.

### 4.1. Подтвердите сохранение перед продолжением

Только после того, как агент подготовил все шесть snapshots, реальные hashes зависимостей и manifest, выполните штатный pre-selection gate. Сначала проверьте версию интерпретатора; `python` ниже означает доступный Python 3.12+ (замените его рабочей командой вашей среды; варианты для Windows — в [development guide](development.md)).

Для следующих команд задайте фактический выбранный путь: PowerShell — `$Case = 'cases/ваш-фактический-id'`, macOS/Linux — `Case='cases/ваш-фактический-id'`. Это обозначение для замены, не буквальный путь; используйте ASCII id своего дела.

```sh
python --version
python tools/case_protocol.py check-candidate "$Case" --revision R0001
```

Успех — реальный JSON со `status: "VALIDATED_CANDIDATE"` и вычисленными `revision_id`/`manifest_sha256`. Gate не публикует дело. Агент выбирает эти точные значения в `ACTIVE.json` последним шагом, без изменения проверенных байтов; после этого проверьте настоящее дело:

```sh
python tools/case_protocol.py classify "$Case"
```

Нужен именно `CHECKPOINTED`, не просто exit 0 или `FRESH`. Сохраните реальные command/stdout/stderr/exit code. Это совместимость файлов, не одобрение стратегии или исполнения. Если `tools/` отсутствует в разрешённом product workspace, оператор выполняет те же команды из доверенного developer checkout с абсолютным путём к делу и передаёт receipt; агент не расширяет себе доступ.

Без успешного gate нельзя выбирать ACTIVE. При `INCOMPLETE/CONFLICT`, ошибке или недоступной проверке остановитесь, сохраните DRAFT и причину; не переписывайте исторические snapshots и не достраивайте manifest предположениями. Подробный контракт — в [шаблоне дела](../cases/_template/README.md).


## 5. Продолжите после перерыва

В новой сессии откройте корень проекта и явно передайте **тот же фактический путь дела**, не имя примера из инструкции. Если путь отсутствует или неоднозначен, агент должен спросить его и остановиться. Попросите продолжить существующую задачу, предварительно прочитав [`resume-revise`](../.agents/skills/resume-revise/SKILL.md). Для продолжения нужен настоящий `CHECKPOINTED` по шагу 4.1 и проверенные зависимости; черновой state или заголовок R0001 этого не доказывает.

Не редактируйте готовые ревизии задним числом. Если контрольные суммы или текущий выбор версии расходятся, продолжение останавливается до восстановления согласованного состояния.

Чтобы исправить или пересмотреть результат, укажите, с каким фактом, выводом или решением вы не согласны, и попросите записать новую ревизию с причиной изменения. Не перезаписывайте папку предыдущей ревизии; правила и остановки при конфликте описаны в `resume-revise`.

Не повторяйте уже завершённые действия. При изменении ревизии/hash, решающего основания или scope старое approval не становится новым разрешением; аналитический пересмотр, выбор направления владельцем и разрешение исполнения — разные шаги.

## Если что-то не получилось

- **Не видны процедуры:** проверьте, что открыта корневая папка, и попросите прочитать `AGENTS.md` и нужный файл из `.agents/skills/`.
- **Недоступен источник или инструмент:** зафиксируйте `NOT RUN` и используйте разрешённую альтернативу либо оставьте вывод неподтверждённым.
- **Непонятно, где остановились:** явно выберите путь дела и попросите RESUME; агент сначала проверит его по Skill, а не начнёт с непроверенного mutable `state.md`.
- **Конфликт ревизий:** не смешивайте версии. Подробнее — [сохранение и восстановление](architecture.md#сохранение-версий-и-восстановление).
- **Папка дела уже существует:** выберите другой `case-id`; не объединяйте новую копию шаблона с существующим делом.
- **Команда копирования не сработала:** сохраните фактическую ошибку. Возможный частичный каталог не объединяйте и не используйте как готовое дело; выберите новый путь с новым согласием либо передайте разбор оператору.
- **Нужно передать ошибку:** сохраните путь дела, выбранную revision, реальную команду/ошибку, stdout/stderr/exit code и версии host/model, если доступны. Не публикуйте credentials, персональные данные и неотредактированную историю чата; неизвестное помечайте UNKNOWN. Не ремонтируйте immutable snapshot ради красивого результата.
